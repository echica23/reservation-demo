# 予約サービスの業務仕様

デモ用に新規設計した仕様。既存システムの実仕様ではない。

## S01 入力

`reserve` は顧客ID、予約日、予約数、1件あたりの価格を受け取る。

- リクエストは必須。
- 顧客IDは必須。空文字・空白のみは不可。
- 予約日は必須。日付の過去・未来による制限は設けない。
- 予約数は1以上10以下の整数。
- 価格は必須で、0より大きいBigDecimal。小数の入力も許可する。
- 不正入力はIllegalArgumentException。外部依存先を呼び出さない。

## S02 在庫と依存先

在庫サービスに予約日と予約数を渡して確認する。在庫がない場合はIllegalStateExceptionで終了し、会員・カレンダーサービスを呼び出さない。在庫がある場合は会員種別と繁忙期かどうかを取得する。

依存先は必ず正常な値を返すものとする。会員種別はNONE・STANDARD・PREMIUMのいずれかであり、nullを返さない。依存先の障害、並行予約、永続化は本デモの対象外。

## S03 割引率

| 会員種別 | 条件 | 割引率 |
| --- | --- | --- |
| PREMIUM | 通常期 | 10% |
| PREMIUM | 繁忙期 | 5% |
| STANDARD | 予約数5以上 | 5% |
| STANDARD | 予約数1～4 | 0% |
| NONE | すべて | 0% |

PREMIUMの割引率は予約数によって変わらない。STANDARD・NONEの割引率は繁忙期によって変わらない。複数の割引は加算しない。結果の割引率は0.10、0.05、0.00として返す。

## S04 金額計算

合計金額 = 価格 × 予約数 × (1 − 割引率)。途中で丸めず、最後に1円単位へHALF_UPで四捨五入する。結果のBigDecimalのscaleは0とする。消費税、手数料、キャンセル料は扱わない。

## S05 公開入口

テスト対象はReservationServiceの公開メソッドreserve。内部メソッドを直接呼び出す必要はない。
